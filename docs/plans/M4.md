# M4 — Mises à jour automatiques

Tranche « mises à jour » de M4. Restent pour plus tard dans M4 : installeur
Inno Setup, `SHA256SUMS.txt` joint aux releases, revue sécurité.

## Objectif

À chaque release GitHub (`v*`), le logiciel détecte la nouvelle version et
affiche un pop-up « Nouvelle mise à jour » avec **Installer** / **Ignorer**.
Paramètres : toggle « Mise à jour automatique », bouton « Vérifier maintenant »,
et bouton « Installer » pour reprendre une mise à jour ignorée.

## État constaté

Déjà en place :

- `tauri-plugin-updater` (Rust) + `@tauri-apps/plugin-updater` (JS), endpoint
  `https://github.com/zFusions/Dollyt/releases/latest/download/latest.json`.
- `UpdateDialog` (Installer / Ignorer), `useAppUpdater` (check au démarrage si
  `autoUpdateApp`, check manuel via event `dollyt:check-update`).
- `ignoredUpdateVersion` persisté dans les settings : ignorer une version ne
  cache que celle-là ; une version suivante re-déclenche le pop-up.
- Workflow `release.yml` sur tags `v*` via `tauri-action`.

Manques :

1. `src-tauri/capabilities/default.json` : aucune permission updater →
   `check()` échoue au runtime. Ajouter `updater:default`.
2. `src-tauri/tauri.conf.json` : pas de `plugins.updater.pubkey` → signature
   invérifiable. Générer la paire (`npm run tauri signer generate`), coller la
   publique dans la config.
3. `.github/workflows/release.yml` : générer les artefacts updater
   (`includeUpdaterJson: true` dans tauri-action) + passer
   `TAURI_SIGNING_PRIVATE_KEY` en env. Le secret GitHub reste à poser par
   l'utilisateur (clé privée jamais commitée).
4. Paramètres : bouton « Installer » quand une version est ignorée
   (`ignoredUpdateVersion`), pour reprendre plus tard comme demandé.
   Implémentation : check manuel → si `update.version === ignoredUpdateVersion`,
   proposer l'installation au lieu de la notice « ignorée ».

## Étapes d'exécution

1. `capabilities/default.json` : ajouter `"updater:default"`.
2. Générer la paire de clés updater ; pubkey dans `tauri.conf.json`
   (`plugins.updater.pubkey`). Afficher la clé privée à l'utilisateur pour
   qu'il la pose en secret GitHub `TAURI_SIGNING_PRIVATE_KEY` (+ éventuel
   `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` si utilisé).
3. `useAppUpdater.ts` : sur check manuel, si la version trouvée est celle
   ignorée, ouvrir quand même le dialogue d'installation (bouton « Installer »
   dans Paramètres via « Vérifier maintenant »). Garder le comportement
   automatique : version ignorée = pas de pop-up au démarrage.
4. `release.yml` : `includeUpdaterJson: true` + env
   `TAURI_SIGNING_PRIVATE_KEY: ${{ secrets.TAURI_SIGNING_PRIVATE_KEY }}`.
   Optionnel : `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` si la clé est chiffrée.
5. i18n : vérifier les clés existantes suffisent (`updateIgnored` notice
   deviendra inutile ou réutilisée).
6. Vérifs : `npm run typecheck`, `npm run lint:rust`, `npm run test:rust`.
   Non vérifiable en local : le flux release réel (nécessite le secret GitHub
   et un tag). Test possible : build release local + `latest.json` manuel —
   non prévu, noté « non vérifié ».
