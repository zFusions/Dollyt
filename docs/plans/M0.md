# Plan M0 — Spike preview

> **Exécution :** skill `executing-plans` ou implémentation directe, tâche par tâche. Context7 avant tout code Tauri 2, Rust, Vite ou React. Skills projet : `dollyt-engine` pour yt-dlp et FFmpeg.

**Objectif :** prouver qu’on peut prévisualiser une vidéo YouTube (itag 18) dans Tauri, définir une plage, télécharger en copie de flux, découper exactement avec FFmpeg. Livrable : rapport de mesures et recommandation go / no-go.

**Architecture :** application Tauri 2 minimale. Rust appelle yt-dlp (`-J`, URL signée du format 18, `--download-sections` avec marge). Interface minimale : champ URL, `<video>`, deux timecodes, bouton « Tester la découpe ». Pas de direction « Chambre noire ». Pas de mock navigateur (réservé à M1+ avec `npm run dev`).

**Spec :** [docs/DESIGN.md](../DESIGN.md) (section Preview), [.cursor/skills/dollyt-engine/SKILL.md](../../.cursor/skills/dollyt-engine/SKILL.md).

## Contraintes globales

- Windows 10 1809+ / 11 x64, WebView2.
- `Command` avec arguments en tableau, `--ignore-config` pour yt-dlp, `CREATE_NO_WINDOW`.
- Pas de `--force-keyframes-at-cuts`. Pas de flux HLS m3u8 pour le téléchargement qualité.
- Découpe : `--download-sections` + marge 2–3 s, MKV temporaire, `ffprobe`, puis FFmpeg une passe.
- Spike jetable : le code peut être réécrit en M1 ; pas de perfection UI.

## Points ouverts (décidés pour le spike)

| Sujet | Décision |
|--------|----------|
| Binaires pour M0 | yt-dlp et FFmpeg sur le PATH de la machine de dev **ou** téléchargement manuel une fois dans `%LOCALAPPDATA%\Dollyt\bin` sans encore le code de hash M1 |
| Vidéo de test | une URL publique courte fixée dans `docs/plans/M0-fixtures.md` (à créer en tâche 1) ; pas de fixture commitée avec données tierces |
| Proxy local | implémenter **seulement** si la lecture directe de l’URL googlevideo dans `<video>` échoue dans WebView2 |
| Deno | installer si yt-dlp l’exige pour la vidéo de test ; noter la version dans le rapport |

## Critères go / no-go

**Go** si : métadonnées `-J`, lecture itag 18 (direct ou via proxy) avec seek et son, téléchargement de section en copie sans ré-encodage yt-dlp, sortie FFmpeg alignée sur les timecodes à ±1 frame ou documenté, temps et CPU notés.

**No-go** si : aucun format muxé utilisable de façon fiable, CSP irréparable sans contournement douteux, ou découpe incohérente non corrigeable par ffprobe.

## Revue à garder en tête

- URL non YouTube refusée côté Rust.
- URL signée expirée : re-résolution avant lecture.
- Vidéo sans itag 18 : repli muxé documenté dans le rapport.
- Annulation d’un processus yt-dlp en cours : arbre tué.

### Tâche 4 — Lecture dans `<video>`

**Fichiers :** composant React minimal, commande `resolve_preview_url`.

### Tâche 5 — Plage et téléchargement

**Fichiers :** commande `download_section`, chemins temporaires sous `%TEMP%` ou `%LOCALAPPDATA%\Dollyt\`.

- Entrée / sortie en secondes (champs simples).
- `--download-sections` avec marge 2–3 s, copie de flux vers MKV.
- Mesurer durée du téléchargement (chrono, pas de promesse).

**Vérification :** fichier MKV présent, `ffprobe` lisible.

---

### Tâche 6 — Découpe exacte FFmpeg

**Fichiers :** `src-tauri/src/ffmpeg.rs`, commande `cut_exact`.

- Une passe FFmpeg : découpe exacte + encode test léger (CRF documenté, ou copie si suffisant pour le spike).
- Pas de preset produit.

**Vérification :** durée de sortie vs plage demandée ; note dans M0-report.
